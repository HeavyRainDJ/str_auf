Критическая ошибка обеих схем: цикл по соседям всё ещё отсутствует. В текущей версии после проверки одного соседа поток возвращается к внешнему циклу. Исправь управляющий поток, а не только подписи.

Используй следующую компактную структуру. В Python должно быть не более 19 видимых блоков, в C++ — не более 20:

1. `Начало`.
2. Ввод данных.
3. Проверка диапазона start/finish; ветвь `Нет` ведёт к выводу ошибки и общему `Конец`.
4. Инициализация `distance`, `previous`, `visited`.
5. `Выбрать непосещённую вершину current с минимальным distance` — начало/следующая итерация внешнего цикла.
6. Ромб `current == -1 или distance[current] == INF или current == finish?`; `Да` ведёт к проверке существования маршрута.
7. Процесс `visited[current] = true; neighbor = 0`.
8. Ромб `neighbor < vertex_count?`; `Нет` возвращается к выбору следующего `current`.
9. Процесс `weight = matrix[current][neighbor]; neighbor = neighbor + 1`.
10. Ромб `weight > 0 и neighbor не посещён?`; `Нет` возвращается к проверке следующего соседа.
11. Только для C++: отдельный ромб `distance[current] <= INF - weight?`; `Нет` возвращается к проверке следующего соседа.
12. Прямоугольник `candidate = distance[current] + weight`.
13. Ромб `candidate < distance[neighbor]?`; `Нет` возвращается к проверке следующего соседа.
14. Процесс обновления `distance` и `previous`; после него поток возвращается к проверке следующего соседа.
15. Проверка существования маршрута.
16. Восстановление и разворот маршрута.
17. Вывод результата либо сообщения `Route not found`.
18. Один общий блок `Конец`.

Если переменная `neighbor` увеличивается до проверки данных, в подписи используй значение текущего соседа без логической ошибки, например `weight = matrix[current][neighbor]; neighbor = neighbor + 1` с отдельным сохранённым индексом либо увеличивай `neighbor` после всех проверок. Предпочтительно использовать процесс `Взять очередные neighbor и weight` и возвращаться к нему после каждой ветви.
